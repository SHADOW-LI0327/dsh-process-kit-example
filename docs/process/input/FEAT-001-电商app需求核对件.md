## 4. 需求理解

- **要解决谁的什么痛点**：验证「装上插件就有流程」—— 在一个**全新空仓**里，一句话需求能否被流程一路推到**能跑、能看、有机器可核验证据**的交付物。
- **边界**：只做 `R-02` 点名的 5 个功能面，且只做两端（`R-01`）。这是**流程贯通性验收**，不是产品打磨；规模由装置自定，刻意做小以跑完全链路。
- **与相邻需求的区别**：本包不含账号 / 权限 / 真实支付 / 持久化 / 后台管理 —— 它们会把链路拉长，却不增加对「流程贯通性」的证明力。
- **本期不做什么**：见 §6。
