## 4. 需求理解

### 4.1 主控的理解

本期要的是**性质变化**，不是功能增量：

1. **有状态**（`R-01`）：应用第一次拥有「记得住」的能力 ⇒ 存储层换掉，且**下单必须成为事务**（建单 + 扣库存 + 清购物车）。
2. **有脸**（`R-02`）：从「桌面后台工具感」变成「手机上的买卖场」⇒ 导航、版式、配色、信息密度全改；**移动优先**。
3. **有命**（`R-04`）：从「跑得起来」到「挂了能查、重启不丢、能备份、能回滚」⇒ 运维面补齐（§2.1 展开③ 的 19 项）。
4. **账号体系（`Q-3` 裁定 = B，本期做）**：引入**最小账号**（邮箱 + 密码或一次性码）⇒ 购物车与订单**归属到用户**、可查「我的订单」、出现真正的**越权面**（只能看自己的车与单，`401`/`403` 由此进入词表）。这会**解除** FEAT-001 的 `N-1` 并**触发 RBAC 全流程**，是本包最大的增量。**真实支付仍不做**（`Q-4` = A：假支付，但 UI 与文档必须**显式标注为演示**）。
5. **商品主图（`Q-5`/`R-05`）**：人的意图是「要有像淘宝那样的商品主图」；主控**否决「外链淘宝图片」的字面实现**（理由见 §5.1），改为**本仓自制 SVG 商品主图**（文本件、离线、零版权风险），商品卡按淘宝形态排版（图上 / 标题两行 / 价格橙红加粗 / 角标）。

| --- | --- | --- |
| 登录时的匿名车 | **并入**账号车：同商品**件数相加**，并受既有件数上限（8）约束；合并后匿名 `cartId` 作废 | 淘宝等主流商城的默认行为；用户加购到一半去登录，**不该丢车** |
| 退出登录 | 回到**匿名车**（新建空车），账号车留在库里不受影响 | 与「换个人用同一浏览器」的直觉一致；也避免退出后仍能看到账号数据 |
| 未登录能否下单 | **不能**（下单端点要求已登录）⇒ 词表新增 `401 UNAUTHENTICATED`；「空车下单」仍是 `409 CART_EMPTY` | `Q-3`=B 的目的是「订单有归属」；允许游客下单会让归属重新落空 |
| 越权面 | 只能读写**自己的**车与单：他人资源返回 `404`（不暴露存在性）而非 `403`；仅「未登录」用 `401` | 沿用 FEAT-001「不暴露内部结构」的口径，最小化信息泄露 |

## 6. 明确不做

| # | 不做项 | 理由 |
| --- | --- | --- |
| `N-1` | 移动端 App / 小程序 / 桌面端 | 沿用 FEAT-001 端范围；本期「淘宝风」= 移动优先的 **Web** |

| `N-8` | 多语言 / 多币种 / 税务发票 | 与本期目标无关 |
| `N-9` | 数据仓库 / BI / 报表 | 同上 |
