### 1.1 成功响应形态

统一为对象包裹，业务载荷放 `data`：

```jsonc
{ "data": <object | array> }
```

- 列表类端点 `data` 为数组；单体类端点为对象。
- **不设** `code: 0` 之类的成功码字段（成功只由 HTTP 状态码表达）。

### 1.2 错误响应形态（**统一，所有 4xx 一致**）

```jsonc
{
  "code": "CART_EMPTY",            // 大写下划线字符串，取自 §四 错误码词表
  "message": "购物车是空的，无法提交订单",  // 面向用户的中文提示，非空
  "details": { }                   // 可选；仅承载字段级校验细节
}
```

- **顶层字段固定为 `code` + `message`（`details` 可选）**，与成功响应的 `data` 互斥。
- **禁止**出现 `stack` / `errno` / 绝对文件路径 / 内部存储对象（`E-13` 断言）。
- HTTP 状态码语义（总纲 §6.4 第 16 条）：**`400` 只留入参非法**；**`404` 资源不存在**；**`409` 有权但此操作对任何主体都不允许**（本包无鉴权 ⇒ 「任何主体」= 任何 `cartId` 持有者）；**`403` 不适用**。
- **两步判别法的本包结论**：本包无鉴权 ⇒ 第①步「该主体对本资源是否本来就有访问权」恒为**是**（任何人可访问任何购物车资源，凭 `cartId` 归属）⇒ 所有「规则不允许」一律走 **`409`**，**不存在 `403`**。
- **`S-16` 注记（纯指向，不新增规范内容，`FEAT-002` 后补）**：本行前提已失效（`FEAT-001` 当期无鉴权）；`FEAT-002` 起有鉴权 —— **未登录 `401`、越权一律 `404`**（不暴露存在性），**仍无 `403` 面**（结论不变，理由变了）。补 `401` 属**新增规范内容**（不是标注），见 `FEAT-002` PRD §1.5 `S-16`，**留待后续包**；本表结构与本行判据一字未改。

| 原子性 | 任一错误 ⇒ **购物车完全不变**（比集合成员与行数，`AC-12`/`AC-14`/`AC-15`/`AC-16`） |
| 承载 `AC` | `AC-10` `AC-11` `AC-12` `AC-13` `AC-14` `AC-15` `AC-16` |

### 3.4.1 `400` 与 `409` 在件数量程上的分界（**澄清，不改词表、不新增码**）

> 同一件事（件数越量程）在不同路径上落**不同码**，此前易被读成「契约与 UI 文案不一致」。按词表既有语义，这是**两条自洽的路径**，分界点是「**入参本身越量程**」还是「**累加后越量程**」：

| 触发方式 | 结果 | 依据 |
| --- | --- | --- |
| `POST` 一次就要 `9`（或 `0` / `-1` / 非整数） | **`400` `INVALID_QUANTITY`** —— 入参本身越量程，与当前购物车状态无关 | 词表 `INVALID_QUANTITY`：`quantity` 非整数 / `<= 0` / `> 8`（`AC-12` `AC-13`） |
| 已有行 `quantity = 8`，再 `POST` `+1`（请求体 `quantity = 1` **合法**，累加后 `9`） | **`409` `QUANTITY_LIMIT_EXCEEDED`** —— 入参合法、操作对任何主体都不允许 | 词表 `QUANTITY_LIMIT_EXCEEDED`：单行件数**累加后**超过 8（`AC-14`） |
| `PATCH` 绝对量 `= 9`（`PATCH` 语义是**覆盖**，非累加） | **`400` `INVALID_QUANTITY`** —— 该请求要写入的值本身就越量程，**永远**不可能成功 ⇒ 属入参非法，不是「有权但不允许」 | 词表 `INVALID_QUANTITY` + 本条 `PATCH` 入参量程 `1..8`（`AC-13`） |
| `PATCH` 绝对量 `= 8` 但库存不足 | **`409`** —— 入参合法、与请求体无关的资源状态不允许 | `OUT_OF_STOCK` / `INSUFFICIENT_STOCK`（`AC-15` `AC-20`） |

> **一句话判据**：**请求体里的数越量程 ⇒ `400`；请求体合法但「当前状态 + 该操作」的结果越界 ⇒ `409`。**
> **与 UI 文案的关系**：UI 在件数达 8 时禁用「＋」并提示「已达上限：单件商品最多买 8 件」—— 若该点击**仍发出请求**，按上表是 `PATCH` 绝对量 `9` ⇒ **`400`**；而 UI 的**禁用态**本身就是 `409` 语义的**前端呈现**（阻止用户做出不允许的操作），两者不矛盾：一条是**服务端返回码**，一条是**前端预防性禁用**，**不要求二者同码**。前端文案与码的映射由 UI 规格定稿，本契约不锁整句（见 §四 末条）。

| `createApp({ seed })` | ~~条数偏离 8~~（**已删除**） | ≥9 条（`AC-16` / `E-02`） | ~~冲突~~ ⇒ **已消除** | `prdVersion` 2 删除条数拒绝口径；默认种子「恰 8 条」改为**正面结构断言**（`E-01` ①） |
