## 三、方案与取舍

### 3.1 端到端主流程（含账号化后的分歧）

```
浏览器(移动优先)                     server(:HOST/:PORT)                 库(DB_PATH, WAL)
  │  GET /                      ─▶ 静态:web/index.html(注入种子数/指纹)      │
  │  GET /api/v1/products       ─▶ 业务路由 ──▶ 读 products                  │
  │  GET /assets/products/*.jpg ─▶ 静态:/assets/** (image/jpeg)              │
  │                                                                          │
  │  匿名态：cartId cookie ⇄ carts(user_id IS NULL)                          │
  │   POST /api/v1/cart/items   ─▶ withTx{ 校验→upsert cart_items }  ────────▶│
  │                                                                          │
  │  注册/登录：POST /auth/register|login ─▶ scrypt 校验/写入 → sessions 行    │
  │      登录成功 ⇒ withTx{ 匿名车并入用户车(件数相加,>8 则整体回滚) → 删匿名车 } │
  │  已登录态：sid cookie ⇄ sessions ⇄ carts(user_id = ?)                     │
  │                                                                          │
  │  POST /api/v1/orders (需登录) ─▶ [鉴权步:无 sid ⇒ 401]                     │
  │       └ withTx BEGIN IMMEDIATE {                                          │
  │            读车行 → 空⇒CART_EMPTY → 逐行条件扣库存(changes=0⇒INSUFFICIENT_STOCK)
  │            → 取号(order_no_seq UPSERT..RETURNING) → 插 orders/order_items  │
  │            → 清 cart_items } COMMIT                                       │
  │  GET /api/v1/orders[/{orderNo}] ─▶ [鉴权步] → 仅本人 / 他人与不存在同形 404 │
  │                                                                          │
  │  GET /health (无前缀,公开)  ─▶ 库探针 SELECT 1 → db.ok ⇒ 200/503          │
  └  反向代理(可选 profile): Caddy 终结 TLS ⇒ 转发 app:3000 (应用只跑 HTTP)     │
```

### 3.3 事务边界与并发（`AC-03` `AC-04` `AC-15` `AC-16` `AC-56`）

| 场景 | 事务范围（**唯一封口**：`store.withTx(fn)`，禁嵌套 —— 实测嵌套会抛） | 原子性断言 |
| --- | --- | --- |
| **下单** | 读车行 → 空车拒绝 → 逐行**条件扣库存**（`changes = 0` ⇒ 抛 `INSUFFICIENT_STOCK`）→ **事务内取号** → 插 `orders` + `order_items` → 清 `cart_items` | 任一步失败 ⇒ **无订单、库存不变、车不清**（`AC-03` `AC-04` `E-14`） |
| **登录合并** | 找/建用户车 → 逐行件数相加（>8 ⇒ 抛 `QUANTITY_LIMIT_EXCEEDED`）→ upsert 用户车行 → 删匿名车 | 越限 ⇒ **两车均保持合并前状态**（`E-19`）；成功后同一商品**只有一行**（`AC-15`） |
| **注册** | 插 `users`（`email` UNIQUE）→ 插 `sessions` — 同一事务（避免"用户建了但没会话"的中间态） | 邮箱重复 ⇒ `409 EMAIL_TAKEN` 且用户数不变（`AC-11`） |
| **迁移** | **每个版本一个事务**：DDL/DML + 写 `schema_migrations` | 中断 ⇒ 该版本整体回滚，无半迁移态（`E-15`） |
| 单项写（加购 / 改件数 / 删行 / 登出） | 单条 `withTx`（内含校验 + 写入） | 失败不留部分写入 |

**并发与竞争（逐条列出，不只写"单实例没事"）**：

| 竞争 | 触发 | 处置 |
| --- | --- | --- |
| 超卖（同商品并发下单） | 同一会话或不同会话同时下单 | `BEGIN IMMEDIATE` 串行化写事务 + 条件 `UPDATE ... WHERE stock >= ?`；`changes = 0` ⇒ 回滚（`AC-04` `E-14`） |
| **订单号重号（跨重启）** | 同 UTC 日重启后取号 | 取号在**事务内**用 `order_no_seq` 的 UPSERT + `RETURNING`（库级计数，跨重启单调）+ `orders.no` **UNIQUE** 兜底（`AC-56`） |
| 同会话并发下单 | 同一会话双提交 | 第一单清车 ⇒ 第二单 `CART_EMPTY`（或库存不足）；订单净增 ≤ 1（`E-10` `E-14`） |
| 登录与加购并发 | 登录事务进行中又来一次加购 | 写事务串行 ⇒ 加购要么落在匿名车（随后被并入）要么落在用户车，**不会丢行**；合并用 `ON CONFLICT DO UPDATE`（件数相加） |
| 匿名车被并入后又用旧 `cartId` | 客户端缓存了旧 cookie | 旧车行已删 ⇒ 按未登录新建空车（**绝不回放已并入的行**，`AC-15`） |
| 会话续期与过期判定并发 | 同一 token 两个并发请求 | 两者都写 `last_seen_at` ⇒ 后写者胜；因是"单调向前"的字段，无业务风险（不断言并发结果） |
| 限流计数并发 | 同会话并发写请求 | 内存计数 + 单线程事件循环 ⇒ 计数不会撕裂；**允许**边界附近 ±1 的行为，故用例重复 3 次（`AC-23`） |
| 读并发（列表 / 详情 / 订单） | 读取时正有写事务 | WAL ⇒ 读不阻塞写；读到的是一致快照 |
| 停机与在途请求 | `SIGTERM` 到达 | 停接新连接 + 等在途完成（上限 10 秒）⇒ 在途下单**落库后**才退出（`E-05`） |

### 3.4 配置项、默认值与启动序（`AC-25` `AC-26`）

- **变量清单与校验规则**：**唯一真源 = 契约 §7.1**（13 项：`HOST` `PORT` `DB_PATH` `SESSION_SECRET` `COOKIE_SECURE` `TRUST_PROXY` `LOG_LEVEL` `BODY_LIMIT_BYTES` `RATE_LIMIT_WINDOW_MS` `RATE_LIMIT_MAX` `BACKUP_DIR` `BACKUP_RETENTION_DAYS` `NODE_ENV`）。本节**不复制**该表（避免两处口径）。
- **启动序（固定，任一步失败 ⇒ 非零退出 + 日志点名原因）**：
  ① 读环境变量 → ② 校验（类型 / 范围 / 必填；`NODE_ENV=production` 时 `SESSION_SECRET` 必填）→ ③ 打开库（父目录可写）→ ④ `PRAGMA journal_mode=WAL` + `foreign_keys=ON` + `busy_timeout` → ⑤ 迁移 + 幂等播种（**库版本超前 ⇒ 拒绝启动**，`E-18`）→ ⑥ 建 `createApp(config)` → ⑦ `listen(HOST, PORT)` → ⑧ 安装信号处理与进程兜底 → ⑨ 打印**一行**启动日志（含监听地址、库路径、schema 版本；**不含**密钥）。
- **默认值来源**：`PORT` 默认 3000（沿用现状）；`HOST` 默认 `127.0.0.1`（**裁定值**：未裁前不默认对外）；`BODY_LIMIT_BYTES` / `RATE_LIMIT_*` / 会话时长 / 口令长度 = **暂定值**（依据 `Q-10` 最小可用假设 + `Q-9`，逐条登记在 PRD §7 `Q-15`~`Q-17`）。
- **测试注入优先于环境变量**：`options.config` 覆盖环境变量（契约 §八.1）⇒ 边界构造不改真实环境。
- **演示数据重置**：提供一条命令（`npm run reset:demo` 或 `scripts/ops/` 下的入口）重建演示库；**生产默认库**同样适用，故文档必须写明「该命令会清空数据」（`Q-7` 的"一条重置演示数据命令"）。

### 3.5 日志、停机与进程兜底（`AC-27` `AC-29` `AC-30` `E-20`）

| 关注点 | 设计 |
| --- | --- |
| 日志形态 | stdout 逐行 JSON；字段与禁止内容 = 契约 §7.5 |
| requestId | 每请求 `randomUUID()`；**贯穿**业务日志、错误日志（`AC-21` 靠它关联）与响应头（可选下发 `X-Request-Id`，便于真机抓包对齐） |
| 慢请求 | `durationMs > 500 ms` ⇒ 加 `slow: true`（阈值暂定值；测试用**注入睡眠**构造，不靠真实慢请求） |
| 客户端中断 | `req` 的 `aborted` / `close`（未完成）⇒ `warn` + `outcome: "client_aborted"`，**不写响应、不计 `error`**（`E-20`） |
| 停机序 | `SIGTERM`/`SIGINT` → 停接新连接 → 等在途（≤10 秒）→ 关库 → 停止时日志 → `exit 0`；超时 ⇒ 强制 `exit 非 0` + `warn` |
| 进程兜底 | `uncaughtException` / `unhandledRejection` ⇒ `error` 日志 + 关库 + **非零退出**（`AC-30`）；**不试图继续服务**（未知状态继续跑更危险） |
| 与容器配合 | `HEALTHCHECK` 命中 `/health`；compose 停止用默认 `SIGTERM` ⇒ 走同一条停机路径（`E-05`） |

### 3.6 备份与恢复（`AC-32` `E-06`；契约 §3.6 为唯一真源）

| 关注点 | 设计 |
| --- | --- |
| 取一致快照 | **首选模块级 `backup(db, path)`**（实测返回 `Promise`）；备选 `VACUUM INTO`。**严禁 WAL 下裸 `cp`** |
| 触发 | `scripts/ops/backup.mjs` 单次入口（宿主机 cron / 容器 sidecar / 手工均可）；**应用进程内不起定时器**（单实例 + 显式运维动作，测试可确定性地构造） |
| 命名与保留 | `BACKUP_DIR/shop-<YYYYMMDD>.db`；保留 **14 天**（`Q-11` 裁定值）；清理只按「相对天数差」判（`> 14 天 ⇒ 删`），时区 / `mtime` 语义差异不进入判据 |
| 失败 | `error` 日志 + 非零退出 + **不删**既有备份（`E-06`） |
| 恢复 | `docs/DEPLOY.md` 给可执行步骤（停服 → 换库文件 → 起服 → `/health` 200）；演练判据 = 恢复后按 `orderNo` 查到订单 |
| 与测试的关系 | 备份 / 恢复判据一律在**临时库 + 临时备份目录**上跑（`BACKUP_DIR` 注入），**不碰生产库**（`AC-07` 的反向对照） |

### 3.7 部署拓扑（`AC-33`~`AC-37`）

浏览器 ──HTTPS──▶ 反代(可选 profile: Caddy)   │   deploy/Caddyfile

| --- | --- | --- |

| 镜像内代码 | 只拷 `server/` `web/` `package.json` `scripts/ops/` | 别把 `docs/` `test/` `reports/` 塞进运行镜像（体积与攻击面） |
| 运维脚本归属 | `scripts/ops/**`（随交付物） | 一次性探针归 `docs/process/tools/FEAT-002/`（属主表口径） |

### 3.8 前端改版与静态面（`R-02` `R-05` `Q-4` `Q-5` `Q-6`）

- **改版方式**：只换视觉与版式，**不丢行为**（`AC-54`）。样式令牌集中在一处（`web/src/styles/**`），旧令牌（`--bg:#0d1117` / `--surface:#161b22` / 主色 `#1f6feb`）**移除而非覆盖**（判据里有"旧值不得残留"的负向断言）。
- **移动优先**：基样式为窄屏（两列商品流 + 底部 Tab），宽屏用 `min-width` 断点增强到居中容器。
- **主图**：8 张**本仓自托管真实照片**（真 JPEG，`P-001.jpg`~`P-008.jpg`；`Q-22` 取代原「自制 SVG」，改名不换位 ⇒ 页面 `src` = `/assets/products/${id}.jpg`，**全同源**）。**含任何外部引用即红**（`AC-48`）—— 照片随仓交付 ⇒ **断网也能显示**、**零第三方请求**；来源与许可落 `web/assets/products/CREDITS.md`（**每张图各自一行、该行含 6 项**：本地文件名 · 商品名 · 作者 · **来源页 URL（照片页，不得用许可 URL 顶替）** · 许可名 · 许可 URL；**判读边界 = `ui-spec` §9.5 的 `R-1`~`R-4`** —— 见 `AC-48` ⑤，与 `UI-67` 同等严格）。**不引任何第三方素材 / 不从淘宝取图**（`AC-52` + `N-2`）。
- **搜索框**：**只作版式位**（存在 + 可聚焦 + 不产生搜索请求），功能面歧义登记在 PRD §7 `Q-14`；UI 规格须给出其形态与文案。
- **演示标注**：结算 / 下单成功 / 页脚至少一处的支付说明含「演示」关键字（`AC-53`）；文案定稿归 UI 规格。
- **静态面**：白名单扩到 `/assets/**` 与 `/favicon.ico`，`CONTENT_TYPES` 加 `.svg`（favicon）与 **`.jpg → image/jpeg`（主图，`Q-22`）**；未知路径 404 收紧为 `text/plain`；路径校验**复用** `resolveWithinWeb`（`AC-50` `AC-51`）。**主图扩展名由 `.svg` 改 `.jpg` ⇒ 白名单与 `CONTENT_TYPES` 不同批改就会重演「8 张全 404」**（`AC-49`）。
- **指纹**：HTML 渲染期注入 `?v=<hash>`；无指纹资源走 `no-cache + ETag`（`AC-31`）。

## 四、数据 / 接口影响

### 4.1 数据模型影响

| 影响 | 内容 |
| --- | --- |
| 新增实体 | `users` · `sessions` · `carts` · `cart_items` · `orders` · `order_items` · `products` · `schema_migrations` + `order_no_seq`（取号用）—— **形状唯一真源 = 契约 §三** |
| 存储载体变更 | 内存 Map → **磁盘单文件库**（WAL）；进程重启**不再重置**（取代 FEAT-001 `AC-30` ②，`S-1`） |
| 不变的部分 | 金额仍是整数分；数量仍是件；种子仍是 8 条（暂定值）；单行件数上限 8、车最多 8 种；订单仍下单即 `paid`（假支付） |
| 关键新增约束 | `users.email` UNIQUE（小写归一）· `orders.no` **UNIQUE** · `cart_items` 复合主键 · `quantity BETWEEN 1 AND 8` · `stock >= 0` · 索引 `orders(user_id, created_at DESC)` |
| 时间口径 | 库内 UTC 毫秒整数；出参 ISO8601 UTC 字符串；**判据只断可解析与相对先后**，不锁时区精度 |

### 4.2 接口形态影响

| 影响 | 内容 |
| --- | --- |
| 端点规模 | FEAT-001 的 8 个 → **15 个**（`keep` 1 / `change` 8 / `new` 6），逐条见契约 §五（`S-18` 登记 FEAT-001 侧"8 个端点"陈述过期） |
| 鉴权面 | 从"无鉴权"变为"最小账号"：出现 **`401`**；**仍无 `403`**（越权一律 `404`）（`S-16` 登记 FEAT-001 契约三处失真的副本） |
| 错误词表 | 8 码 → **15 码**（新增 `UNAUTHENTICATED` `INVALID_CREDENTIALS` `EMAIL_TAKEN` `INVALID_PAGINATION` `PAYLOAD_TOO_LARGE` `RATE_LIMITED` `INTERNAL_ERROR`）；**`500` 不再伪装 `404`**（`S-14`） |
| 静态面 | 放行范围扩 `/assets/**` `/favicon.ico`；`.svg → image/svg+xml`（favicon）· **`.jpg → image/jpeg`（主图，`Q-22`）**；未知路径 404 收紧为 `text/plain`（`S-13`） |
| 分页 | `GET /products`（默认 200 / 上限 200）与 `GET /orders`（默认 20 / 上限 100）新增 `limit`/`offset`；非法 ⇒ `400 INVALID_PAGINATION` |
| 兼容性 | 上述变化**均为本期授权范围**（对照件 `R-01` `R-04`）；消费方只有本仓前端，**无需灰度 / 版本共存** |

### 4.3 权限与数据范围

- 角色：**匿名** 与 **`user`** 两种；无管理面、无 RBAC 表（权限码清单见契约 §4.5，是文档层口径）。
- 数据范围：`own` —— 已登录只能看/改**自己的**车与订单；匿名只能碰自己那辆匿名车。
- 越权口径（写死）：未登录 ⇒ `401 UNAUTHENTICATED`；他人资源 ⇒ `404 NOT_FOUND`（与不存在同形）；**无 `403`**。
- 敏感数据：口令与盐**只在库内**；响应 / 日志 / 错误体一律不含（`AC-18`）。
- 与 FEAT-001 的差异：本包**首次**出现"主体"概念 ⇒ 所有"归属"类判据的取样点必须落在**会话身份 ≠ 资源归属**的错位处（`AC-17` `AC-19`）。

## 五、非目标

沿用 PRD §2（`N-1`~`N-9`），设计侧补充三条**明确不做**：

1. **不做多实例 / 无状态化 / 共享会话存储**（`Q-8` = A 单实例；会话落本地库）。
2. **不做迁徙 / 双写 / 兼容旧内存数据**：没有需要迁移的既有生产数据（FEAT-001 数据本是内存态、重启即失）。
3. **不做前端构建 / 打包 / TS 编译**：仍为原生 ES Module 直出，指纹靠运行时注入。

## 六、风险与回退

| # | 风险 | 影响 | 缓解 / 回退 |
| --- | --- | --- | --- |

| `RD-3` | **测试污染生产库** | 真实数据被毁 | 契约 §八.3 强制临时库 / `:memory:`；`AC-07` 断言生产库路径前后无变化 |
