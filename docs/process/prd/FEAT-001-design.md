### 3.1 端到端主流程

> 「谁 → 在什么场景 → 做什么」逐步写，作为验收的预期对照。

1. **顾客**打开首页 → 服务端托管 `web/index.html` → 浏览器请求 `/api/v1/products` → **看到 8 件商品**（名称 + 元价）。
2. **顾客**按名称点开一件商品 → 请求 `/api/v1/products/{按名称解析出的 id}` → **看到名称 / 描述 / 分价换算成元的价 / 库存**。
3. **顾客**点「加入购物车」→ 若无 `cartId` 先下发 cookie → `POST /api/v1/cart/items {productId, quantity:1}` → 购物车多一行，页头徽标 +1。
4. **顾客**再点一次 → 同一商品**仍是一行**、件数 2、行小计与总额同步。
5. **顾客**试着把件数改成 9 → `PATCH` 被 `409 QUANTITY_LIMIT_EXCEEDED` 拒 → **数字保持 8 不变**。
6. **顾客**清空后加 2 件不同商品 → `POST /api/v1/orders`（无 body）→ 返回 `status: "paid"` + `orderNo` → **库存按购买件数减少**、**购物车清空**。
7. **顾客**打开订单列表 → `GET /api/v1/orders` → **最近一单在最上面**，含订单号 / 已支付 / 元价总额。
8. **顾客**换一个无痕窗口（新 `cartId`）→ 购物车为空、订单为空（`AC-30` / `E-09`）。

### 3.2 前端交互

> 各端各自的入口、组件、跳转、空态与异常态。**视觉数值、组件复用判定、文案整句定稿由 UI 规格承担**（`prd/FEAT-001-ui-spec.md`），此处只给**交互骨架与状态清单**（供 UI 规格逐格填值）。

- **`web/`（Web 前端，5 页）**：
  - **入口**：`GET /` 直开首页（无登录、无路由守卫、无构建步骤）。
  - **页面与跳转（下单为两步，与 §一 `R-02` 行页面清单一致）**：`商品列表`（点商品名 → 详情）→ `商品详情`（「加入购物车」→ 留在本页并更新徽标；「去购物车」→ 购物车）→ `购物车`（改件数 / 删行 / 「去结算」→ **结算页**）→ **`结算页`**（复核行项与总额、「提交订单」→ 下单成功跳 `订单列表`；空车 / 库存不足等错误态**在本页呈现**，见下方异常态口径）→ `订单列表`（可从结算成功后跳入，也可从页头直入）。
  - **状态清单（每页必填六格，值由 UI 规格定）**：默认态 / 加载态 / 空态（列表为空或购物车为空时的提示）/ 错误态（4xx 后的用户可见提示与是否可重试）/ 无权限态 —— **本包无鉴权 ⇒ 该格填「不适用 + 原因：无鉴权」**，不得留空 / 禁用态（如件数已达上限 8 时「加一件」是否禁用）。
  - **异常态口径**：`409 CART_EMPTY` / `409 INSUFFICIENT_STOCK` / `409 QUANTITY_LIMIT_EXCEEDED` / `409 CART_FULL` / `409 OUT_OF_STOCK` / `404 NOT_FOUND` / `400 INVALID_*` 全部须有**可读中文提示**并**保持页面状态不变**（数字不回弹、不出现半成品行）。
  - **可见文案锚点**：商品名（列表与详情都用名称定位，不用主键）、价格（元、两位小数）、件数、订单号、订单状态（「已支付」）、空车与库存不足的提示关键字。
  - **AC 覆盖**：`AC-27`（页面可达 + 商品锚点 + ESM）；交互层的**机器**断言面**主动**收窄为 HTTP / jsdom 结构断言（理由：零依赖 / 快 / 可重复，**不是缺浏览器** —— 核对件 §9 后补正）；真机交互由 UAT 用 CDP 驱动浏览器黑盒取证。

## 四、数据 / 接口影响

> 只描述**契约层影响**并与契约互指，**不复制判据字面、不写 SQL / DDL / 索引实现 / 迁移方案**。

### 4.1 数据模型影响

| 实体 | 字段 | 类型 | 约束 / 取值 | 影响（新增 / 修改 / 复用） |
| --- | --- | --- | --- | --- |
| `Product` | `id` `name` `description` `priceCents` `stock` | `string`×3 / `integer`×2 | 名称唯一非空；`priceCents > 0`；`stock >= 0` | **新增**（空仓新建，无既有实体可复用） |
| `Cart` | `cartId` `items` `quantityTotal` `totalCents` | `string` / `CartItem[]` / `integer`×2 | `items.length ∈ [0, 8]`；两个合计字段由行推导 | **新增** |
| `CartItem` | `productId` `productName` `unitPriceCents` `quantity` `lineTotalCents` | `string`×2 / `integer`×3 | `quantity ∈ [1, 8]`；`lineTotalCents = unitPriceCents × quantity` | **新增** |
| `Order` | `orderNo` `status` `items` `itemCount` `totalCents` `createdAt` `paidAt` | `string`×4 / `OrderItem[]` / `integer`×2 | `orderNo` 全局唯一；`status ∈ {"paid"}`；金额 / 件数为正整数 | **新增** |
| `OrderItem` | `productId` `productName` `unitPriceCents` `quantity` `lineTotalCents` | `string`×2 / `integer`×3 | 下单时快照 | **新增** |

> **是否触及数据层 schema 变更**：**否**。本包为**内存态**（`Q-1` 裁定 / `N-3`），无表、无列、无迁移 ⇒ **列变更 = 无 / 数据补偿 = 无需 / 回滚方式 = 重启进程即回种子初值**。Gate 摘要**不需要**提请人点头 schema 变更（本包不在该场景内），但请在 Gate1 摘要中照此口径写明「本包无 schema 变更」，以免被误判为漏报。
> **唯一跨重启的不变量**：重启后一切回种子初值（`AC-30` 断言）。

### 4.2 接口形态影响

| 端点 | 方法 | `alignment` | 影响说明 |
| --- | --- | --- | --- |
| `/api/v1/products` | `GET` | `new` | 只读列表；无分页 / 无查询参数；出参 `Product[]` |
| `/api/v1/products/{id}` | `GET` | `new` | 路径参数 `id`；不存在 → `404 NOT_FOUND` |
| `/api/v1/cart` | `GET` | `new` | 读 cookie `cartId`；缺失 / 非法即下发新 cookie 并返回空车；出参整车 |
| `/api/v1/cart/items` | `POST` | `new` | body `{productId, quantity}`；重复加购**合并累加**；6 类错误（见契约 §四） |
| `/api/v1/cart/items/{id}` | `PATCH` | `new` | body `{quantity}` 为**覆盖**语义；6 类错误 |
| `/api/v1/cart/items/{id}` | `DELETE` | `new` | 无 body；行不存在 → `404 NOT_FOUND` |
| `/api/v1/orders` | `POST` | `new` | **无 body**；副作用 = 扣库存 + 清空车 + 入订单列表；3 类错误（`CART_EMPTY` / `INSUFFICIENT_STOCK`） |
| `/api/v1/orders` | `GET` | `new` | 仅本 `cartId` 订单，倒序；无分页 |
| `/` · `/src/**` | `GET` | `new` | 静态托管，与 API **同端口**；未知静态路径 `404` 且不得 5xx |

### 4.3 权限与数据范围

- **权限码**：**无**。本包无账号、无令牌、无 RBAC（核对件 `N-1`）⇒ **无权限码清单，无 `403` 面**。契约 §四 已就此写「缺席声明」，任何 `403` 断言判不合格。
- **鉴权口径**：**不鉴权**。唯一的「身份」是匿名 `cartId` cookie，它回答的是「这辆车是谁的」，**不是「你有没有权」** —— 任何人拿到 `cartId` 即可操作该车（本包接受该风险：无账号、无敏感数据、内存态）。**`cartId` 属归属标识而非凭据，故不得据此产生 `403`**。
- **数据可见范围**：**按 `cartId` 隔离**，无组织 / 区域 / 角色维度。
  - 购物车：只见自己的车（`E-09` 断言两个客户端 `items` 的 `productName` 集合互斥）。
  - 订单：只见自己 `cartId` 的订单（`E-09`）。
  - 商品：**全局只读可见**（种子，无归属）。
  - 库存：全局共享可变（`AC-19` / `AC-20` / `E-08`），跨客户端可见 —— 这是**拒绝超卖**的必要条件。
