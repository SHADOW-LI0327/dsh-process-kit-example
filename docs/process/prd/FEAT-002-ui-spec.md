### 9.3 原型图上的现状与过渡（**如实登记，不假装已完成**）

- **本轮原型（`docs/process/prototypes/FEAT-002/**`）的主图仍是几何占位图形**，不是照片。原因：出图引擎（`PhotoCraft CLI 0.6.0`）的 `run` **只提供 `shape.create` / `type.create` 两类图元，没有任何「导入图片 / 置入文件」命令**（已实测：`image.create` 为 unknown command，registry 里也无 place/import 类命令）⇒ 生成器无法把 JPEG 合成进分层 PSD。
- 因此本轮原型**只证明版式**：主图位的**尺寸、圆角、`aspect-ratio`、与标题/价格/角标的相对关系**与照片版本**完全一致**（照片替换不改变任何几何）。主图的**内容正确性**由 §9.2 的题材台账 + `UI-67` 承担。
- 原型目录下已附一份**取材样例**（`prototypes/FEAT-002/assets/P-00N.jpg`，落点与命名同交付物）供人眼与 dev 参照；**它只是样例集，不是交付物**（交付物是 `web/assets/products/P-00N.jpg`，由 dev 落盘并按 `UI-67` 登记 `CREDITS.md`）。

### 9.5 `CREDITS.md` 的**格式无关判读边界**（`R-1`~`R-4`）

> 本节只规定**「能不能被稳定判读」**，不规定唯一排版 —— 表格行 / `—`·`–`·`·`·`/`·制表符分隔的单行 / 项目符号行（`- `）配「作者：/来源页：/许可：」显式标注 / 作者写成 `[名字](url)` 或 `<url>` 自动链接 / 单元格内 `\|` 转义竖线，**任一写法都算合规**。

| 编号 | 判读要求（不满足即判红） |
| --- | --- |
| `R-1` | 每张图**单独一行**：不把一个文件的多个字段拆到多行，也不把多张图挤在同一行 |
| `R-2` | 该行的 URL 里必须有**非许可类的「照片页 URL」**：`creativecommons.org/licenses/…` 这类**许可 URL 不能顶替来源页**（两者都给最好；判读时按非许可类 URL 取来源页） |
| `R-3` | 该行必须有一个**既不是 URL、也不是许可名、也不是文件名**的文本字段当**作者**（带「作者：」标注更稳） |
| `R-4` | URL 不得被换行符 / 空格**截断**，也不得写成 **HTML 实体**（如 `&amp;`）—— 需要时给 URL 编码后的原文即可 |

> **为什么要有本条**：原 `UI-67` 字面只要求「登记来源 URL 与许可」，**允许实现者只给许可 URL 而把来源页整列删掉** ⇒ 那是一条**假绿通道**（机器判绿、人却查不到照片出处）。本节的 `R-2` 就是关掉这条通道；`R-1`/`R-3`/`R-4` 是保证**能被稳定解析**、不因排版差异被误判。
