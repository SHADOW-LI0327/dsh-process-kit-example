## 二、验收项（`U-NN`）

### A 组 · 功能 / 账号 / 数据面（用户可感知行为）

### U-01 五面全流程可用

- **判定判据**：存量五面回归（`AC-55`）· UI行为继承（`AC-54`）· 演示标注显式（`AC-53`）
- **具体怎么试**：从首页开始，把**列表 → 详情 → 加购 → 购物车 → 结算 → 提交订单 → 订单列表**完整走一遍；中途在结算页留意支付说明；再回列表与详情各看一眼。
- **期望观察**：五面**全部可用**，没有一处报错、白屏或丢数据；结算页能看到「演示支付」这类**显式标注**（不涉及真实资金）；改版后既有交互（加减件数、删行、进详情）**仍然好用**。

### U-02 重启数据仍在

- **判定判据**：重启数据仍在（`AC-01`）
- **具体怎么试**：登录后加购一件商品并成功下单一笔，**记下订单号**；请主控**重启服务**（同一份数据）；刷新页面（必要时重新登录）。
- **期望观察**：重启后**账号仍能登录**、**那笔订单还在列表里**、购物车内容与下单后的库存数**都是重启前的值** —— 不再出现「重启即重置」。

### U-03 换会话就换人

- **判定判据**：隔离语义保留（`AC-02`）
- **具体怎么试**：用账号 A 放好购物车、下过单；另开**全新无痕窗口**（或另一个 cookie 罐）当访客 B，看购物车与订单；A 回头看自己的。
- **期望观察**：B 看不到 A 的购物车与订单；A 的东西**仍在**。**重启服务后**再各看一次，隔离关系**不变**。

### U-04 注册即开会话

- **判定判据**：注册即开会话（`AC-10`）· 账号字段非法（`E-02`）
- **具体怎么试**：用一个**没注册过的邮箱** + 合规口令注册；随后**不重新登录**直接加购并下单。HTTP 侧再试：邮箱格式非法（如 `abc`）、口令 7 位、口令 129 位、缺字段、口令传数字。
- **期望观察**：注册成功即**已登录**（页头有账号入口，订单入口可用）、可直接下单；四类非法输入**都被拒**且提示可读，**不泄露「该邮箱是否已注册」**（与不存在邮箱的失败提示**看不出区别**）。

### U-05 重复注册拒绝

- **判定判据**：重复注册拒绝（`AC-11`）
- **具体怎么试**：用**同一邮箱**再注册一次。
- **期望观察**：被拒并提示**邮箱已被使用**；原账号**不受影响**（重新登录后购物车与订单**都还在**）。

### U-06 登录与会话属性

- **判定判据**：登录即开会话（`AC-12`）· 会话畸形过期（`E-01`）
- **具体怎么试**：用正确凭据登录，抓一次响应头看会话 cookie；再把该 cookie **改一个字符**（伪造）或**删掉**后访问受保护面与购物车面。
- **期望观察**：登录成功且会话 cookie 的**四项属性齐备**（`HttpOnly` / `Secure`（HTTPS 下）/ `SameSite` / `Path` —— 逐项对照 PRD `AC-12` 的清单，看不到就记「看不到」）；伪造 / 缺失 cookie 时**受保护面 `401`**、购物车面按**新匿名车**处置（`200` + 新 cookie），**不报 5xx**。

### U-07 登录失败不辨

- **判定判据**：登录失败不辨（`AC-13`）
- **具体怎么试**：① 用**正确邮箱 + 错口令**登录；② 用一个**从没注册过**的邮箱 + 任意口令登录。
- **期望观察**：两次都失败，**提示文案逐字一样**（都是凭据不正确），**看不出**邮箱到底存不存在；两次都不算登录成功。

### U-08 未登录拒下单

- **判定判据**：未登录拒下单（`AC-14`）· 已登录空车下单（`E-11`）
- **具体怎么试**：① **未登录**状态下往车里加一件商品，直接点「提交订单」；② **登录后**把车清空，再点「提交订单」。
- **期望观察**：① 被拒并提示**需要登录**，购物车**没被清空**、也没产生订单；② 提示**购物车是空的**（**不是**「请先登录」）—— 两种提示**必须能区分**。

### U-09 匿名车并入账号车

- **判定判据**：匿名车并入账号车（`AC-15`）· 合并且越限（`E-19`）
- **具体怎么试**：① 未登录时加购 2 件不同商品（例如《陶瓷滤杯》×1、《手摇磨豆机》×1），然后**登录**；② 再构造一次「并入后单行会超过 8 件」的场景（账号车里某商品已 6 件、匿名车里同商品 3 件），然后登录。
- **期望观察**：① 登录后**两件都并进账号车**、件数**相加**、匿名车作废；② 超限那次**被拒**并提示超上限，**合并不发生** —— 账号车与匿名车**都保持并入前的样子**（没有半并进去的中间态）。

### U-10 退出回到匿名车

- **判定判据**：退出回到匿名车（`AC-16`）
- **具体怎么试**：登录状态下看好自己的车与订单；点**退出登录**；再看购物车页与订单页。
- **期望观察**：退出后是**一个新的空匿名车**；账号车与**已下订单不受影响**（重新登录后原样还在）。

### U-11 我的订单归属与越权

- **判定判据**：我的订单归属（`AC-17`）· 越权返404（`AC-19`）· 订单号不存在（`E-03`）
- **具体怎么试**：账号 A 下一单、记下订单号；换账号 B 登录，**手工请求 A 的订单号详情**；再用一个**格式合法但从不存在**的订单号请求详情。
- **期望观察**：B 的订单列表**只有 B 自己的**；请求 A 的单返回「**找不到**」且**看不出**它到底存不存在；不存在的订单号返回的响应**与「他人订单」逐字相同**（两者**必须无法区分**）。

### U-12 下单三件事与重复提交

- **判定判据**：下单事务原子（`AC-03`）· 重复提交下单（`E-10`）
- **具体怎么试**：加购 2 件，记下**下单前的库存**；提交订单；**立刻再点一次**「提交订单」；回购物车与商品页看。
- **期望观察**：第 1 次成功（建单 + 扣库存 + 清车**三件事都发生**）；第 2 次被拒并提示**购物车是空的**；订单列表**只多了一单**；购物车是空的；库存**正好少了买走的件数**。

### U-13 分页与越量程

- **判定判据**：商品分页可选（`AC-08`）· 订单分页倒序（`AC-09`）· 分页越量程（`E-09`）
- **具体怎么试**：下一笔单后在订单列表**翻页**（若有分页控件）；HTTP 侧对 `/api/v1/products` 与 `/api/v1/orders` 试 `limit` 的**两端点值**与**两端外一单位**，再试 `offset=-1`。
- **期望观察**：默认页内返回且**不多不少**；订单**最近一单在最上**；两端点值**通过**、越界与 `offset=-1` **被拒**（提示可读，不是 5xx）。

### U-14 订单号重启不重号

- **判定判据**：订单号重启不重号（`AC-56`）
- **具体怎么试**：下单一笔记下订单号 → 请主控**重启服务** → **同一天内**再下一笔。
- **期望观察**：两个订单号**不同**；**两单都在列表里**；历史订单没被顶掉。

### U-15 无界面全链路

- **判定判据**：无界面直连可用（`E-13`）
- **具体怎么试**：**只用 curl**（显式 cookie jar）走完：注册 → 登录 → 加购 → 下单 → 查单 → 请主控重启 → 再查单。
- **期望观察**：每一步都可达、状态码与预期一致；**重启后订单仍可查**；没有「只有点界面才能触发」的动作。

### U-16 错误响应形态统一

- **判定判据**：错误词表完备（`AC-20`）· 内部错误不伪装（`AC-21`）· 静态白名单外（`E-16`）
- **具体怎么试**：收集一批错误：不存在的商品、不存在的订单号、坏 JSON、非法分页、未登录、超限件数；另访问 `/server/**` 与一个**不支持的扩展名**（如 `/foo.png`）。
- **期望观察**：所有错误都是**同一种形状**（`code` + 中文 `message`），**没有**英文堆栈、没有文件路径、**没有**把静态路径伪装成业务 `404` 带商品文案；**不得**出现 5xx。
- **登记（预期无法判定）**：`AC-21` 的 **500 分支**（未预期异常）黑盒**构造不出** —— 必须注入故障。遇到即如实记「无法判定」，**不要**记「不通过」。

### U-17 浅底白卡

- **判定判据**：浅底白卡配色（`AC-38` / `T-1`）
- **具体怎么试**：真浏览器打开首页与详情页，看页面底色与内容卡底色；在**全页**范围内搜旧深色令牌（首轮口径：`#0d1117` / `#161b22`）。
- **期望观察**：页面底**浅灰**、内容卡**纯白**；旧深色配色**一处都不残留**；不必判「好不好看」。

### U-18 主色橙红与价格

- **判定判据**：主色橙红取值（`AC-39` / `T-2`）
- **具体怎么试**：看主按钮 / 当前 Tab / 价格的色；量价格的**字号与字重**，并对比价格里 `¥` 与数字的大小。
- **期望观察**：主色是**橙红系**；价格是**橙红加粗大字**且 `¥` **小于**数字；色值与 PRD 判据给出的示例若有差距，**记录实测值与差距**交人裁（`U-52`），不自行判负。

### U-19 双列卡流与移动优先

- **判定判据**：双列商品卡片流（`AC-40` / `T-3`）· 移动优先布局（`AC-47` / `T-10`）
- **具体怎么试**：先用**手机宽度**（390 宽）看首页，看列数与卡内元素顺序、标题是否两行截断；再拉到**宽屏**（1280）看是否居中、有无横向滚动条。
- **期望观察**：窄屏**两列**、卡内顺序为**图 → 标题（两行截断）→ 价格**；宽屏居中且**没有横向滚动条**；两种宽度下都**不破版**。

## 四、人工 / 真机边界项（需 curl / 并发 / 真机驱动，界面点不出来或需时序观察）

### U-48 并发不超卖

- **判定判据**：并发下单不超卖（`AC-04`）· 同会话并发下单（`E-14`）
- **具体怎么试**：① 把某商品买到**只剩 1 件**，用**两个不同会话**同时（背靠背）各下单这件 1 件；② 再用**同一个会话 / 同一辆车**同时提交两单。
- **期望观察**：① **恰好 1 单成功**，另一单被拒（库存不足 / 车已空）；之后库存**恰好 0**（**绝不能为负**）；② 同会话并发也**最多 1 单成功**，另一单被拒。
- **注意**：这条是**人工并发**，不保证每次都撞得上；若两次请求时间差明显（第 1 单已成功且库存归零），本次**不构成并发证据** ⇒ 如实记「未覆盖并发」，**不得**记「通过」。

### U-49 首帧与提交中的可观察态（真机 · 无 PRD 判据锚点）

- **判定判据**：**本条不挂任何 PRD `AC` / `E`** —— 它观察 **UI 规格** `UI-27`（首帧「加载中…」占位）与 `UI-28`（「提交中…」按钮禁用态）。这两条**没有 PRD 锚点**，故不在自动化断言面；**这是观察面登记，不是新增产品判据**。
- **具体怎么试**：① 打开首页 / 详情 / 订单列表，**看首帧**数据到达前是否有「加载中…」占位（可限速或看首屏快照）；② 在结算页点「提交订单」，**在响应返回前**看按钮是否禁用 + 文案「提交中…」；③ 同一时刻**再点一次**，数实际发出的下单请求条数。
- **期望观察**：① 首帧出现**可读的占位**（不是白屏、也不是无反馈的静止页）；② 提交期间按钮**禁用**且文案变「提交中…」；③ 连点**只产生 1 次**下单请求。
- **注意**：③ 与 `E-10`（服务端对**已发出**的第二次请求回 `409`）**不是同一件事** —— 本条看的是**前端压根没发第二次**。两者都通过才算好。
- **证据要求**：截图或网络请求清单，落 `reports/uat/evidence/FEAT-002-uat/`；装置拿不到首帧快照时**如实记「未覆盖」**并写明限制。

### U-50 件数上限禁用态（真机 · `UI-11`，UAT 承载）

- **判定判据**：**本条不挂任何 PRD `AC` / `E`** —— 它观察 **UI 规格** `UI-11`（件数到 8 时该行「＋」**禁用**、真实点击**不产生请求**、件数保持 8；件数为 1 时「－」同理）。`AC-13`/`AC-14` 只说「上限 8」这条规则，**不描述「禁用态」这一 UI 承载** ⇒ 由本条承接（**观察面登记**）。
- **具体怎么试**：真浏览器加购一件商品 → 在购物车页把该行件数点到 **8** → ① 看「＋」是否禁用；② 在**这个已禁用的按钮上真实点击**一次并抓网络请求；③ 把件数减到 **1**，看「－」是否同样禁用。
- **期望观察**：件数 **8** 时「＋」禁用，点击**请求 0 条**、件数仍 8、**不出现**新提示；件数 **1** 时「－」同样禁用。
